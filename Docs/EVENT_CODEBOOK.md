# Choice Overload — Event Codebook

## Version

Experiment version:

```text
v0.4.0
```

Event-codebook version:

```text
1.1
```

This document describes the event markers generated by the Choice Overload experiment for EEG and eye-tracking synchronization.

The MATLAB source of truth is:

```matlab
P.Events
```

defined in:

```text
Initialize/initializeParameters.m
```

The exact codebook used during each participant session is also stored in:

```matlab
R.Events
```

inside the participant result file.


---

# Event Routing

All task-level events are routed through:

```matlab
sendEvent(P, T, taskName, eventName, eventCode)
```

Two forms of event information are used:

- `eventCode` — numeric trigger sent to EEG hardware
- `eventName` — descriptive event message sent to systems such as eye tracking

Task routing supports:

```text
Acquisition
PreferenceRating
Choice
```

Questionnaire events are routed through:

```text
Choice
```

because the questionnaire occurs as part of successful Choice trials.


---

# EEG Trigger Protocol

The EEG trigger interface uses a serial trigger connection.

Hardware constraints:

```text
Interface:
Serial USB trigger

Valid experimental trigger range:

1–63
```

Trigger code:

```text
0
```

is reserved as the hardware idle state and is not used as an experimental event.

At initialization:

```matlab
fwrite(serialPort,0)
```

is sent once to place the trigger interface in a known idle state.

The experiment validates:

- no configured event code exceeds `63`
- no two configured event codes are identical

| Code | Event |
|---:|---|
| 55 | Acquisition Synchronization |

This marker indicates that acquisition systems have been initialized and synchronized.

Typical event name:

```text
ACQUISITION_SYNC
```

This event is used for alignment between:

- behavioral task timing
- EEG recording
- eye-tracking recording

# Choice Exposure Events

Choice exposure is the primary experimental manipulation.

Exposure codes uniquely identify:

```text
Set Size × Experimental Condition
```

Current set sizes:

```text
6
12
24
```

Current experimental conditions:

| Abbreviation | Condition |
|---|---|
| UL | Uniform Least |
| UM | Uniform Moderate |
| UH | Uniform High |
| CF | Clearly Favored |
| RS | Random Set |


## Exposure Code Matrix

| Set Size | UL | UM | UH | CF | RS |
|---:|---:|---:|---:|---:|---:|
| 6 | 30 | 31 | 32 | 33 | 34 |
| 12 | 35 | 36 | 37 | 38 | 39 |



A missed Choice trial produces:

```text
22       CHOICE_FIXATION

30–44    CHOICE_EXPOSURE

23       CHOICE_MASK

24       CHOICE_RESPONSE_ONSET

26       CHOICE_MISS
```

The questionnaire is skipped after a missed Choice response.

# Timing Semantics

Stimulus-onset markers are sent immediately after their corresponding Psychtoolbox:

```matlab
Screen('Flip', ...)
```

Response markers are based on the response collection system.

Reaction times are measured relative to the corresponding onset flip.

Choice fixation, exposure, and mask durations use flip-anchored absolute timing:

```matlab
WaitSecs('UntilTime', onset + duration);
```

This prevents event transmission execution time from extending the intended visual duration.

# Backend Behavior

- The event logger can remain active in debug mode.
- EEG receives numeric codes when its task route is enabled and the serial backend is active.
- EyeLink receives descriptive event names when its task route is enabled and recording is active.
- Code `55` is routed through the `Acquisition` task after EyeLink recording starts.
- Each participant result stores the exact `P.Events` structure used for the session.
